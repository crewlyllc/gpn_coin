### Note (2026-11-26 05:2x PT) — `Essential task ... failed` is the shutdown path, not a dead node

Read the day lines' termination counts with this in hand. Over the 7 days to 2026-11-26 the fleet
journal carries **23** `Essential task`txpool-background` failed. Shutting down service.` lines. Every
one of the 23 shares its timestamp **to the second** with systemd's `Stopping gpn-fleet.service` line
(`journalctl --user -u gpn-fleet.service -o short-iso | grep -E "Stopping gpn-fleet|Essential task"`,
2026-11-20 20:50:33 … 2026-11-25 21:05:49). It is upstream sc-service reporting the txpool background
task's future resolving during a requested stop — the node is being stopped, it did not die.

So the line is **noise on a clean stop**, and it is already classified as planned when
`scripts/soak-record.py::restart_audit` finds the `Stopping` line within ±2 lines. Do not read a
termination count as crashes, and do not "root-cause" these: the causes measured are the loop's own
fleet redeploys (2026-11-25 09:13:39, 13:49:59 — all gpn-\* units restarted in the same second) and the
updater's apply (21:05:49). The genuinely unclassified case stays what it always was: a node whose
journal has **no** `Stopping` line and shows `Main process exited` / `Scheduled restart job` instead.
