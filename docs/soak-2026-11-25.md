### Note (2026-11-26 05:2x PT) — `Essential task ... failed` is the shutdown path, not a dead node

Read the day lines' termination counts with this in hand. Over the 7 days to 2026-11-26 the fleet
journal carries **23** `Essential task`txpool-background` failed. Shutting down service.` lines. Every
one of the 23 shares its timestamp **to the second** with systemd's `Stopping gpn-fleet.service` line
(`journalctl --user -u gpn-fleet.service -o short-iso | grep -E "Stopping gpn-fleet|Essential task"`,
2026-11-20 20:50:33 … 2026-11-25 21:05:49). It is upstream sc-service reporting the txpool background
task's future resolving during a requested stop — the node is being stopped, it did not die.

So the line is **noise on a clean stop**, and it is already classified as planned when
`scripts/soak-record.py::restart_audit` finds the `Stopping` line within ±2 lines. Do not read a
termination count as crashes, and do not "root-cause" these: the causes measured are the loop's own
fleet redeploys (2026-11-25 09:13:39, 13:49:59 — all gpn-\* units restarted in the same second) and the
updater's apply (21:05:49). The genuinely unclassified case stays what it always was: a node whose
journal has **no** `Stopping` line and shows `Main process exited` / `Scheduled restart job` instead.

### Note (2026-11-26 05:4x PT) — day 2's first number, `32.53 s`, was a 65-second window

Day 2 first recorded `effective block interval (2 blocks in 0.02 h): **32.53 s** ⚠️ drift`. That is
not the day's cadence: a loop pass made the day's *first* reading at 13:19:24Z (height 367623) and
the timer's record 65 s later measured from it, so two blocks became a headline figure at 2× the
truth. Cause, read in `scripts/soak-record.py::select_prev`: a same-day re-run preferred
`day_first[today]` over the last reading of the previous day, and `effective_interval_secs` accepted
any window over 60 s.

Fixed on `main` in this pass: `select_prev` now measures from the **last reading of a previous day**
(`day_last`, newly written each run; a legacy `last` from an earlier date is used when no per-day
history exists) and only falls back to the day's first reading on the soak's first day; the minimum
window is 900 s, so a sub-15-minute span reports `n/a` instead of a number. Proof: `python3
scripts/tests/test-soak-record.py` ⇒ **103 checks passed, 0 failed** (7 new, including "a 65 s window
is not a cadence figure — it is n/a, not 32.53 s"); the same fixtures against the pre-fix
`select_prev` return `{'height': 367623}` → `32.5`, i.e. the exact wrong number this record carried.

Day 1's reading (height 364487 at 23:57:00Z) was restored into `~/.gpn/soak-state.json`
`day_last["2026-11-25"]` because `last` had been overwritten before `day_last` existed; the value is
the one day 1's own section records.
