## MinNodeVersion (spec 42, planned)

* Design: `docs/design/design-min-node-version.md`
* Operator-facing behaviour: `docs/updates.md` §5.3
* Why it is staged and not applied: it is a chain-wide runtime change, which in
  this repo is always review-first (proposal → committee approve → execute →
  `System.set_code`). It also does not *need* to be applied for the cutoff to
  work today: the node-side check against the signed release manifest already
  ships and is active (`gpn-agent/src/update.rs`, `GPN_STANDBY` in
  `gpn-node/node/src/service.rs`).

### To build it (only after the design review says go)

```bash
# 1. implement pallet-gpn-governance::MinNodeVersion + NodeVersionApi
#    (sketched in the design doc), bump spec_version 41 -> 42
# 2. build the runtime WASM on its own — NEVER `cargo build` the canonical one
cd gpn-node
cargo build -p gpn-runtime --release --features std
#    wasm-builder emits target/release/wbuild/gpn-runtime/gpn_runtime.compact.compressed.wasm
cp target/release/wbuild/gpn-runtime/gpn_runtime.compact.compressed.wasm \
   ../wasm/gpn_runtime_spec42_min_node_version.compact.compressed.wasm
sha256sum ../wasm/gpn_runtime_spec42_min_node_version.compact.compressed.wasm
```

### To apply it (a human with the committee keys, deliberately separate)

Use the governance pipeline — `docs/upgrades-governance.md`, tool
`gpn-agent/src/bin/gpn_gov_upgrade.rs`:

```bash
E=ws://<unsafe-rpc-node>:9944
gpn_gov_upgrade stage   ../wasm/gpn_runtime_spec42_min_node_version.compact.compressed.wasm --endpoint $E
gpn_gov_upgrade propose --plan .state/gov-upgrade/spec42_staged<…>.plan.json --signer <member-A>
gpn_gov_upgrade approve <proposal hash> --signer <member-B>      # 2-of-3 committee
# ... 17 280 blocks (3 days) ...
gpn_gov_upgrade execute <proposal hash> --signer <any funded key>  # -> Root -> set_code
gpn_gov_upgrade verify --plan .state/gov-upgrade/spec42_staged<…>.plan.json
# then check: specVersion == 42, :code == the plan's code hash, and the
#             MinNodeVersionChanged event on the executing block
```

`gpn_upgrade_runtime` (Sudo.sudo → System.set_code) is **dev/testnet only**; the mainnet sudo
key is the inert all-zeros placeholder.

Do **not** apply a runtime `set_code` from an automated task, and do not touch
genesis (`chain_spec.rs` / the bundled WASM) as part of a staged change.
