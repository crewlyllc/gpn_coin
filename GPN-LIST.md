# GPN list — the only queue

**Every item has exactly one of four states.** No others exist.

| state | meaning |
|---|---|
| `NEW` | added, not yet in a version |
| `IN-PROGRESS` | bundled into a version that is being built/released |
| `COMPLETE` | shipped: version published, checklist fully ticked, node reports it |
| `BLOCKED` | cannot be completed now — reason recorded, and what would unblock it |

## The loop

1. Items are added as `NEW`.
2. Starting a version: **bundle every `NEW` item**, mark them `IN-PROGRESS`.
3. `scripts/make-release-checklist.py <version>` copies the generic checklist and inserts every
   `IN-PROGRESS` item at the right place.
4. The cron works that checklist in order, ticking each box with evidence.
5. When every box is ticked **and** the version is published **and** a node reports it from its
   running process, the bundled items become `COMPLETE`.
6. Bundle the next batch of `NEW` items.

A `BLOCKED` item stays on the list with its reason; its checklist line is ticked
`blocked — <reason>` so it never holds a release hostage.

Nothing is ever deleted. `COMPLETE` and `BLOCKED` rows are the record.
