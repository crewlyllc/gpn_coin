## Step 6 — (BLOCKED) Provider must accept the job
Job #1 sat in `Pending` state. The `gpn_llm_provider` only picks up `Running` jobs, so the
provider must first ACCEPT it. Two prerequisites were missing on the freshly-reset chain:

### 6a. Provider registration — `ProviderNotRegistered`
```
POST /providers/register (min_gflops=150)  → HANGS (no response)
```
The provider is attested but NOT registered in the marketplace (attestation ≠ registration).
The `register_provider` call hangs (subxt submit blocks / no response, no logged error).

## RESULT
✅ Wallet funded (100 GPN) and a paid LLM job was created (job #1, 10 GPN, Pending).
❌ The provider couldn't be registered → couldn't accept → inference never ran → no payout.

## Root cause to fix
`POST /providers/register` (ComputeMarketplace::register_provider) hangs in the gpn_api /
ChainClient `submit_signed_call`. The attestation + registration + accept chain has a gap:
after a chain reset, the provider's marketplace REGISTRATION is wiped (separate from
attestation) and the re-register call hangs. Needs investigation + fix before the full
"wallet → pay → run AI → get result" loop can complete end-to-end.
