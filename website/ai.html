Why a proxy?

The testnet access point listens on plain http://…:8092, which a browser on an HTTPS page cannot call. gpncoin.ai/api/* terminates TLS at the edge, rate-limits per IP, and forwards the same request — so your code only ever talks to https://gpncoin.ai.

Copy & paste

Pick your environment

Same request every time — what changes is the quoting. Pasting bash into PowerShell is the usual way this goes wrong, so the samples below are split by environment and each one is written in that environment's own idiom. The testnet ignores the API key, but the OpenAI SDK still requires one: any non-empty string works.

Runs on: PowerShell 5.1+ (shipped with Windows 10 1803+ and Server 2019+). Two traps: curl in PowerShell is an alias for Invoke-WebRequest — you must type curl.exe to get real curl — and line continuations are a backtick, not a backslash.

powershell 
$body = '{"model":"llama3.2:1b","max_tokens":32,"messages":[{"role":"user","content":"What is the capital of Kenya? One word."}]}'

$body | curl.exe -sS --max-time 150 `
  https://gpncoin.ai/api/v1/chat/completions `
  -H "Content-Type: application/json" `
  --data-binary "@-"
powershell · extract the answer 
# uses $body from the block above
$r = $body | curl.exe -sS --max-time 150 `
  https://gpncoin.ai/api/v1/chat/completions `
  -H "Content-Type: application/json" `
  --data-binary "@-" | ConvertFrom-Json

$r.choices[0].message.content

The JSON body goes in on stdin on purpose: it never passes through PowerShell's argument parsing, so no escaping is involved. Inline -d '{"model":"…"}' is the classic failure — Windows PowerShell 5.1 re-quotes the argument and the inner double quotes are lost, so curl receives malformed JSON. If you do need it inline on 5.1, escape as -d '{\"model\":\"llama3.2:1b\"}'; PowerShell 7.3+ passes arguments verbatim instead, so those backslashes must be dropped there. The stdin form above behaves the same on both.

import time
import requests

    f"{API}/images/generations",

Economics

What a token costs, and why

GPN does not price tokens off a competitor's price list, and it does not price them off a GPU-rental market either. It prices them off throughput: one anchor constant — what a 4060-class card earns per hour — divided by the token rate that card actually achieves on a 1B model. The formula below is the one running in gpn_scheduler today, default constants included, so you can check the arithmetic. Read the caveats before the table: today's testnet inference is free and the models are small.

The comparison this is not

GPN's quality tier today is small open models (0.5B–14B) on consumer GPUs — currently llama3.2:1b, qwen2.5, deepseek-r1, plus LoRA tunes. It is not a frontier model, and nothing here claims GPT-class reasoning. You are buying cheap inference of a small model, not a 1T-parameter agent. Every row in the table below carries its model class so the comparison is not rigged by omission.

The buyer's price does not depend on the GPU — on purpose

GPN publishes one global price per token. A 4060 and an H100 charge the buyer the same $0.38 per million output tokens; the difference is what the provider earns per hour ($0.10 vs $1.23). That is a deliberate design choice: a per-GPU price would make the cheapest card the only one ever selected, and no spot market of heterogeneous hardware can run that way. It is also why FP32 TFLOPs are the wrong metric — decode of a small model is memory-bandwidth-bound, so pricing on FLOPs would rank a 4090 above an H100. The curve is built on measured throughput instead.

Image pricing — the same anchor, a different work unit

A diffusion job has no token count, so it is priced on GPU-seconds: the cost of a render is pixels × denoise steps, plus a fixed per-job pipeline load. The two constants below are measured on the same 4060-class anchor card that sets the token price (sd-turbo through gpn_diffuse.py, one process per render — the model load is part of every job):

seconds = 30.0 + (MPx × steps × frames) × 0.73     # measured, sd-turbo on the anchor 4060

measured:  512²  @  8 = 28.9 s      512²  @ 20 = 36.5 s
           768²  @ 12 = 35.7 s     1024²  @ 20 = 44.7 s

usd = seconds / 3600 × $0.10/hr × (1 + 30% margin)   # the same anchor rate as tokens
gpn = usd ÷ token_price

Provider side: same fee per image, more images per hour

Every card is paid the same pre-margin fee for the same image (~$0.00088), but a faster card finishes sooner: a 4060 needs 31.5 s (~114 images/hr, $0.10/hr), a 4090 8.5 s (~423/hr, $0.371/hr), an H100 2.6 s (~1,406/hr, $1.232/hr). GPU-seconds are interpolated by the card's own curve rate — only the 4060 is measured. Video uses the same formula with a frames term and a bigger model load, but is marked blocked: LTX-Video's T5 text encoder does not fit an 8 GB card, so its constants are estimates, not measurements.

How the number is derived

Straight from the access-point scheduler. One tunable constant — the hourly earning of a 4060-class card — is divided by the token rate that card reaches on a 1B model, giving k, the pre-margin price of one output token. Margin is added on top, and the GPN amount is the dollar price converted at the on-chain token price.

anchor_tok_s = roofline(30,000 GFLOP/s, 272 GB/s, 1B)
             = min(6000 compute, 95.2 memory) = 95.2 tok/s
anchor_rate  = $0.10/hr            # GPN_GPU_ANCHOR_USD_HR
k            = 0.10 / (95.2 × 3600) = $2.918e-7/token
price_out    = k × (1 + 0.30)     # GPN_MARGIN_BPS=3000
price_in     = price_out × 0.15   # GPN_INPUT_RATE_FRAC
escrow       = prompt_tokens/4 + max_tokens   (output-equivalents)
gpn/tok      = price_out ÷ token_price_usd

A provider's hourly earning is the same k applied to its own roofline throughput: roofline(gflops, bandwidth, params) × 3600 × k. Margin does not touch k — it is the buyer-side spread. The legacy oracle-market model is still selectable with GPN_PRICING_MODEL=market for A/B comparison.

Worked example

The 4060-class anchor: 30,000 GFLOP/s FP32, 272 GB/s memory bandwidth, one llama3.2:1b stream.

roofline(1B) = min(30000e9×0.40 / (2×1e9),   # compute
                   272e9×0.70    / (2×1e9))  # memory
             = min(6000, 95.2) = 95.2 tok/s

k        = 0.10 / (95.2 × 3600) = 2.918e-7
price    = 2.918e-7 × 1.30 = 3.793e-7 / token
         → $0.379 per 1M output tokens
         → $0.057 per 1M input tokens (15%)
gpn/tok  = 3.793e-7 / 0.15 = 2.53 GPN per 1M

Decode is memory-bound, so the 1B ceiling comes from bandwidth, not FLOPs. The same card on a 7B model drops to ~13.6 tok/s and earns the provider ~$0.014/hr — which is exactly the case the below-cost warning exists to surface. Model size changes the provider's economics, not the buyer's price.

Where the money goes

🖥️ Provider

95% of the job charge. The marketplace takes MarketplaceFeeBps = 500 (5%) at settlement. Escrow covers prompt_tokens/4 + max_tokens output-equivalents and the unused remainder is refunded; the charge is the blended token rate × actual tokens. The provider is the one who ran the GPU — that is the whole point of the design.

🏦 Protocol fee

The 5% lands in the token pallet and splits by default 200/150/100/50 bps: 40% staking rewards, 30% treasury, 20% burned, 10% oracle rewards. The burn is a real slash — total issuance falls, not just bookkeeping.

🪙 Emission

50 GPN per 15 s block ≈ 288,000 GPN/day to miners under the halving schedule, capped at ~420.48M emitted, plus a fixed 100M treasury (70M genesis-unlocked, 30M vested) — a hard ceiling of ≈520.5M GPN. Fees are separate from emission: they recycle GPN, they do not mint it.

Scale check: at 2.53 GPN per million tokens, one day of emission (288,000 GPN) buys ≈114 billion output tokens — about 13,000 consumer GPUs running flat out for a day. That is the size of the inference economy the current parameters can subsidise.

Honest caveats

  • Today's inference is free, and that is not a price. The public access point pays job escrow from a hot wallet, so gpncoin.ai/api/v1 costs you nothing while the testnet runs. This section describes the paid model the scheduler is already built for — not what is live.
  • The token has no reliable market price. GPN is a testnet token. Any USD figure here is an illustrative conversion at $0.15/GPN; the GPN-denominated numbers are the real ones. When the on-chain oracle feed is empty (it is today), token_price_usd also falls back to $0.15 — so a change in the feed changes both sides of the ratio.
  • Throughput is measured, not promised. The anchor assumes a 4060-class card reaching 95 tok/s on a 1B model; a slower card earns less per hour, and a card earning below its operator's declared cost is flagged rather than quietly subcontracted. Batching several sequences on one card raises the provider's earning per hour without changing the buyer's price.
  • Small models are not frontier models. A $0.40/M hosted nano model and a $0.38/M GPN 1B model are both "cheap", but neither reasons like gpt-6-astra or Claude Fable 5.1. Cost per useful answer is the only fair denominator, and this page does not have that data.
  • Input metering is channel-first. The default off-chain channel bills input at 15% of the output rate. The on-chain pallet stores a single rate, so an on-chain job publishes a blended rate that is exact when the completion runs to max_tokens and slightly under-bills short completions. Exact two-rate settlement on-chain needs a pallet change; it is tracked, not claimed.
  • No cache pricing, no batch discount, no SLA on the testnet.

Free, but not unmetered

The testnet access point pays escrow from a hot wallet, so a call costs you nothing. Each call is still one GPU job — hence the per-IP cap. For volume, run your own access point or provider node.

Testnet caveats

Prompts and answers are not private (the AP and provider see them; results are stored off-chain). Models are small. No uptime promise — the network is a testnet.
