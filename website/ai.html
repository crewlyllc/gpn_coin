Ask the network

This form calls POST /api/v1/chat/completions on gpncoin.ai. The Worker proxies it over HTTPS to the access point. The access point routes by job value: a short answer is cheap enough to settle on an off-chain escrow channel (batched, well under a second), while an expensive request settles per job on chain and leaves its own receipt. Send "mode": "settle" or "mode": "channel" to pin a path.

Why a proxy?

The testnet access point listens on plain http://…:8092, which a browser on an HTTPS page cannot call. gpncoin.ai/api/* terminates TLS at the edge, rate-limits per IP, and forwards the same request — so your code only ever talks to https://gpncoin.ai.

Copy & paste

Pick what you want to do

Two steps: choose what you want to generate, then the environment you'll call it from. The request shape is the same everywhere — what changes is the quoting, and pasting bash into PowerShell is the usual way this goes wrong. The testnet ignores the API key, but the OpenAI SDK still requires one: any non-empty string works.

One request, five environments. Every sample asks the same question — “What is the capital of Kenya? One word.” — so you can see exactly what changes between them.

Runs on: PowerShell 5.1+ (shipped with Windows 10 1803+ and Server 2019+). Two traps: curl in PowerShell is an alias for Invoke-WebRequest — you must type curl.exe to get real curl — and line continuations are a backtick, not a backslash.

powershell 
$body = '{"model":"llama3.2:1b","max_tokens":32,"messages":[{"role":"user","content":"What is the capital of Kenya? One word."}]}'

$body | curl.exe -sS --max-time 150 `
  https://gpncoin.ai/api/v1/chat/completions `
  -H "Content-Type: application/json" `
  --data-binary "@-"
powershell · extract the answer 
# uses $body from the block above
$r = $body | curl.exe -sS --max-time 150 `
  https://gpncoin.ai/api/v1/chat/completions `
  -H "Content-Type: application/json" `
  --data-binary "@-" | ConvertFrom-Json

$r.choices[0].message.content

The JSON body goes in on stdin on purpose: it never passes through PowerShell's argument parsing, so no escaping is involved. Inline -d '{"model":"…"}' is the classic failure — Windows PowerShell 5.1 re-quotes the argument and the inner double quotes are lost, so curl receives malformed JSON. If you do need it inline on 5.1, escape as -d '{\"model\":\"llama3.2:1b\"}'; PowerShell 7.3+ passes arguments verbatim instead, so those backslashes must be dropped there. The stdin form above behaves the same on both.

powershell 
$body = @{
  model      = "llama3.2:1b"
  max_tokens = 32
  messages   = @(@{ role = "user"; content = "What is the capital of Kenya? One word." })
} | ConvertTo-Json -Depth 5

$r = Invoke-RestMethod -Uri "https://gpncoin.ai/api/v1/chat/completions" `
  -Method Post `
  -ContentType "application/json" `
  -Body $body `
  -TimeoutSec 150

$r.choices[0].message.content

No quoting to think about — PowerShell serialises the hashtable and parses the reply for you, so the answer is just $r.choices[0].message.content. -TimeoutSec 150 matters: a cold job runs 20–90 s and the default is 100 s. On older Windows 10 builds add [Net.ServicePointManager]::SecurityProtocol = 'Tls12' first if TLS fails.

Live. Three steps in every language: submit (answers 202 in milliseconds with an id), poll the id until status is completed (a 512×512 render takes ~25–35 s), then download data[0].url — a PNG whose sha256 matches the bytes the provider signed. Polling is free; only the render is billed.

Runs on: PowerShell 5.1+ on Windows 10 1803+ or Server 2019+. Same two traps as text — type curl.exe, and continue lines with a backtick.

powershell · curl.exe (submit → poll → download) 
$API = "https://gpncoin.ai/api/v1"

# 1. submit: 202 with an id, a poll_url and the price
$body = '{"model":"sd-turbo","prompt":"a cozy cabin at dusk, warm windows","size":"512x512","steps":8}'

$job = $body | curl.exe -sS -X POST "$API/images/generations" `
  -H "Content-Type: application/json" `
  --data-binary "@-" | ConvertFrom-Json

Write-Host "job $($job.id) $($job.status) $($job.gpn.price_gpn) GPN"

# 2. poll every 2 s — the render takes ~25-35 s
while ($job.status -eq "pending") {
  Start-Sleep -Seconds 2
  $job = curl.exe -sS "$API/images/generations/$($job.id)" | ConvertFrom-Json
}

if ($job.status -ne "completed") { throw "render failed: $($job.error)" }

# 3. download the provider-signed PNG
curl.exe -sS $job.data[0].url -o cabin.png
Get-Item cabin.png | Select-Object Name, Length

Only the submit response carries poll_url; the poll response does not, so the loop rebuilds the URL from $job.id. Downloading data[0].url is the documented path; GET $API/images/$($job.id) serves the same bytes if you'd rather keep the id.

powershell · Invoke-RestMethod (submit → poll → download)

(Get-Item cabin.png).Length

No quoting, no ConvertFrom-Json — the reply is already an object, so $job.data[0].url is the PNG and $job.gpn.payment tells you how it settled.

Runs on: bash or zsh with curl and jq (install jq from your package manager — or use the macOS tab, which parses with python3 instead).

bash · submit → poll → download 
API=https://gpncoin.ai/api/v1

# 1. submit: 202 in milliseconds
job=$(curl -sS -X POST $API/images/generations \
  -H 'Content-Type: application/json' \
  -d '{"model":"sd-turbo","prompt":"a cozy cabin at dusk, warm windows","size":"512x512","steps":8}')
id=$(echo "$job" | jq -r .id)
echo "job $id — $(echo "$job" | jq -r .status)"   # 202: pending, with the price quoted

# 2. poll every 2 s until the render finishes (~25-35 s)
while :; do
  out=$(curl -sS $API/images/generations/$id)
  status=$(echo "$out" | jq -r .status)
  [ "$status" = pending ] || break
  sleep 2
done
[ "$status" = completed ] || { echo "render failed: $(echo "$out" | jq -r .error)"; exit 1; }

# 3. download the PNG the provider signed
curl -sS "$(echo "$out" | jq -r '.data[0].url')" -o cabin.png
file cabin.png   # PNG image data, 512 x 512

Polling costs nothing and returns status, then data[].url once completed. Add "sync":true to hold the connection instead — allowed only when the estimate is under 60 s (512×512 @ 8 steps ≈ 31 s yes; 1024×1024 @ 50 steps ≈ 68 s is refused with the estimate). Images expire after 24 h; expires_at says when.

Runs on: the default zsh on any current macOS — curl and Python 3 ship with the OS, so there is nothing to install (no jq either).

python · requests (submit → poll → download) 
import time
import requests

API = "https://gpncoin.ai/api/v1"

# 1. submit: 202 -> pending, with the price already quoted
job = requests.post(
    f"{API}/images/generations",
    json={"model": "sd-turbo",
          "prompt": "a cozy cabin at dusk, warm windows",
          "size": "512x512", "steps": 8},
    timeout=60,
).json()
print(job["id"], job["status"], job["gpn"]["price_gpn"], "GPN")

# 2. poll every 2 s; build the URL from the id (only the submit reply has poll_url)
while job["status"] == "pending":
    time.sleep(2)
    job = requests.get(f"{API}/images/generations/{job['id']}", timeout=30).json()

if job["status"] != "completed":
    raise SystemExit(f"render failed: {job.get('error')}")

# 3. download the provider-signed PNG
png = requests.get(job["data"][0]["url"], timeout=60)
png.raise_for_status()
open("cabin.png", "wb").write(png.content)
print("saved cabin.png", len(png.content), "bytes", job["gpn"]["payment"])

The result carries gpn.payment = "channel" when the request was batched off-chain or "onchain" when it settled per job on chain (with its own job_id receipt) — never both. Images expire after 24 h; expires_at says when.

Live. Three steps, same shape as images: submit a base model plus {prompt, completion} pairs (answers 202 immediately), poll until status is succeeded or failed, then either chat with the returned model name (tuned-<id>) or download the LoRA adapter zip. A 1-example tune of HuggingFaceTB/SmolLM2-135M-Instruct took ~3.5 min end to end on 2026-10-23; a larger base model and more epochs take proportionally longer. Limits: 200 pairs, lora_r 1–128, epochs 1–10, 50 GPN flat per tune, 4 submissions per hour per IP. Polling is free.

bash · curl + jq (submit → poll → download → chat) 
API=https://gpncoin.ai/api/v1

# 1. submit — 202 in ~0.1 s with an id and a poll_url
JOB=$(curl -sS -X POST "$API/finetunes" -H 'Content-Type: application/json' -d '{
  "model": "HuggingFaceTB/SmolLM2-135M-Instruct",
  "dataset": [{"prompt": "Say hi.", "completion": "Hi! Nice to meet you."}],
  "lora_r": 1,
  "epochs": 1
}')
echo "$JOB" | jq -r '"\(.id) \(.status) \(.tuned_model)"'
ID=$(echo "$JOB" | jq -r .id)

# 2. poll — queued -> running -> succeeded (2026-10-23: ~3.5 min)
while :; do
  JOB=$(curl -sS "$API/finetunes/$ID")
  ST=$(echo "$JOB" | jq -r .status)
  echo "$ST"
  [ "$ST" = succeeded ] && break
  [ "$ST" = failed ] && { echo "$JOB" | jq -r .error; exit 1; }
  sleep 5
done
echo "$JOB" | jq -r .tuned_model        # tuned-<id>

# 3a. download the LoRA adapter (zip: adapter_model.safetensors + tokenizer)
curl -sS "$API/finetunes/$ID/artifact" -o adapter.zip
unzip -l adapter.zip

# 3b. or skip the file and talk to the tuned model directly
MODEL=$(echo "$JOB" | jq -r .tuned_model)
curl -sS -X POST "$API/chat/completions" -H 'Content-Type: application/json' -d "{
  \"model\": \"$MODEL\",
  \"messages\": [{\"role\": \"user\", \"content\": \"Say hi.\"}]
}" | jq -r '.choices[0].message.content'

The submit reply is the only one carrying poll_url; the poll response does not, so the loop rebuilds the URL from $ID. The adapter is served as a zip (adapter_model.safetensors, adapter_config.json, tokenizer) — about 1.5 MB for a 135M base. The tuned model is registered on the provider that trained it, so tuned-<id> answers on the normal chat endpoint.

python 3 · stdlib only (submit → poll → download) 
import json, time, urllib.request

API = "https://gpncoin.ai/api/v1"
HEADERS = {"Content-Type": "application/json",
           "User-Agent": "gpn-finetune-demo/1"}   # or Cloudflare refuses Python-urllib

def call(method, path, body=None):
    data = json.dumps(body).encode() if body is not None else None
    req = urllib.request.Request(API + path, data=data, method=method, headers=HEADERS)
    with urllib.request.urlopen(req) as r:
        return r.status, json.load(r)

status, job = call("POST", "/finetunes", {
    "model": "HuggingFaceTB/SmolLM2-135M-Instruct",
    "dataset": [{"prompt": "Say hi.", "completion": "Hi! Nice to meet you."}],
    "lora_r": 1,
    "epochs": 1,
})
print(status, job["id"], job["status"], job["tuned_model"])   # 202 6528 queued tuned-6528

while True:
    _, job = call("GET", f"/finetunes/{job['id']}")
    print(job["status"])
    if job["status"] in ("succeeded", "failed"):
        break
    time.sleep(5)

assert job["status"] == "succeeded", job.get("error")
print(job["tuned_model"], job["result_hash"])

req = urllib.request.Request(f"{API}/finetunes/{job['id']}/artifact", headers=HEADERS)
with urllib.request.urlopen(req) as r, open("adapter.zip", "wb") as f:
    f.write(r.read())

A 202 is not an error: urlopen only raises for status ≥ 400, so the submit falls through normally. result_hash is the commitment the provider submitted on-chain — it is not the zip's sha256, so use sha256sum adapter.zip only to compare two downloads. Set a User-Agent — the CDN in front of gpncoin.ai answers 403 to the default Python-urllib/3.x string (verified 2026-10-23).

node 18+ · fetch (submit → poll → download) 
import { writeFile } from "node:fs/promises";

const API = "https://gpncoin.ai/api/v1";
const post = (path, body) =>
  fetch(API + path, {
    method: "POST",
    headers: { "content-type": "application/json" },
    body: JSON.stringify(body),
  });

// 1. submit — 202 + id + poll_url
let res = await post("/finetunes", {
  model: "HuggingFaceTB/SmolLM2-135M-Instruct",
  dataset: [{ prompt: "Say hi.", completion: "Hi! Nice to meet you." }],
  lora_r: 1,
  epochs: 1,
});
console.log(res.status);                          // 202
const job0 = await res.json();                    // { id: "6528", status: "queued", … }
console.log(job0.id, job0.status, job0.tuned_model);
const { id } = job0;

// 2. poll — queued -> running -> succeeded
let job;
do {
  await new Promise((r) => setTimeout(r, 5000));
  job = await (await fetch(`${API}/finetunes/${id}`)).json();
  console.log(job.status);
} while (job.status === "queued" || job.status === "running");
if (job.status !== "succeeded") throw new Error(job.error);

// 3. the adapter zip, or chat with job.tuned_model
const zip = await fetch(`${API}/finetunes/${id}/artifact`);
await writeFile("adapter.zip", Buffer.from(await zip.arrayBuffer()));

Top-level await needs an ES module (.mjs or "type": "module"). A response body can only be read once — take the id from the parsed object, not from a second .json() call.

Capabilities

What you can run today

The job API accepts every GPN work type, but each card below tells you exactly how far that type has actually got. live = running now and reachable from this page; shipped, not wired = the code exists and has completed jobs on the testnet, but there is no public endpoint to call it yet; coming soon = nothing you can call.

💬 Text / LLM live

Economics

What a token costs, and why

GPN does not price tokens off a competitor's price list, and it does not price them off a GPU-rental market either. It prices them off throughput: one anchor constant — what a 4060-class card earns per hour — divided by the token rate that card actually achieves on a 1B model. The formula below is the one running in gpn_scheduler today, default constants included, so you can check the arithmetic. Read the caveats before the table: today's testnet inference is free and the models are small.

The comparison this is not

GPN's quality tier today is small open models (0.5B–14B) on consumer GPUs — currently llama3.2:1b, qwen2.5, deepseek-r1, plus LoRA tunes. It is not a frontier model, and nothing here claims GPT-class reasoning. You are buying cheap inference of a small model, not a 1T-parameter agent. Every row in the table below carries its model class so the comparison is not rigged by omission.

The buyer's price does not depend on the GPU — on purpose

GPN publishes one global price per token. A 4060 and an H100 charge the buyer the same $0.38 per million output tokens; the difference is what the provider earns per hour ($0.10 vs $1.23). That is a deliberate design choice: a per-GPU price would make the cheapest card the only one ever selected, and no spot market of heterogeneous hardware can run that way. It is also why FP32 TFLOPs are the wrong metric — decode of a small model is memory-bandwidth-bound, so pricing on FLOPs would rank a 4090 above an H100. The curve is built on measured throughput instead.

Image pricing — the same anchor, a different work unit

A diffusion job has no token count, so it is priced on GPU-seconds: the cost of a render is pixels × denoise steps, plus a fixed per-job pipeline load. The two constants below are measured on the same 4060-class anchor card that sets the token price (sd-turbo through gpn_diffuse.py, one process per render — the model load is part of every job):

seconds = 30.0 + (MPx × steps × frames) × 0.73     # measured, sd-turbo on the anchor 4060

Provider side: same fee per image, more images per hour

Every card is paid the same pre-margin fee for the same image (~$0.00088), but a faster card finishes sooner: a 4060 needs 31.5 s (~114 images/hr, $0.10/hr), a 4090 8.5 s (~423/hr, $0.371/hr), an H100 2.6 s (~1,406/hr, $1.232/hr). GPU-seconds are interpolated by the card's own curve rate — only the 4060 is measured. Video uses the same formula with a frames term and a bigger model load, but is marked blocked: LTX-Video's T5 text encoder does not fit an 8 GB card, so its constants are estimates, not measurements.

How the number is derived

Straight from the access-point scheduler. One tunable constant — the hourly earning of a 4060-class card — is divided by the token rate that card reaches on a 1B model, giving k, the pre-margin price of one output token. Margin is added on top, and the GPN amount is the dollar price converted at the on-chain token price.

anchor_tok_s = roofline(30,000 GFLOP/s, 272 GB/s, 1B)
             = min(6000 compute, 95.2 memory) = 95.2 tok/s
anchor_rate  = $0.10/hr            # GPN_GPU_ANCHOR_USD_HR
k            = 0.10 / (95.2 × 3600) = $2.918e-7/token
price_out    = k × (1 + 0.30)     # GPN_MARGIN_BPS=3000
price_in     = price_out × 0.15   # GPN_INPUT_RATE_FRAC
escrow       = prompt_tokens/4 + max_tokens   (output-equivalents)
gpn/tok      = price_out ÷ token_price_usd

A provider's hourly earning is the same k applied to its own roofline throughput: roofline(gflops, bandwidth, params) × 3600 × k. Margin does not touch k — it is the buyer-side spread. The legacy oracle-market model is still selectable with GPN_PRICING_MODEL=market for A/B comparison.

Worked example

The 4060-class anchor: 30,000 GFLOP/s FP32, 272 GB/s memory bandwidth, one llama3.2:1b stream.

roofline(1B) = min(30000e9×0.40 / (2×1e9),   # compute
                   272e9×0.70    / (2×1e9))  # memory
             = min(6000, 95.2) = 95.2 tok/s

k        = 0.10 / (95.2 × 3600) = 2.918e-7
price    = 2.918e-7 × 1.30 = 3.793e-7 / token
         → $0.379 per 1M output tokens
         → $0.057 per 1M input tokens (15%)
gpn/tok  = 3.793e-7 / 0.15 = 2.53 GPN per 1M

Decode is memory-bound, so the 1B ceiling comes from bandwidth, not FLOPs. The same card on a 7B model drops to ~13.6 tok/s and earns the provider ~$0.014/hr — which is exactly the case the below-cost warning exists to surface. Model size changes the provider's economics, not the buyer's price.

Where the money goes

🖥️ Provider

95% of the job charge. The marketplace takes MarketplaceFeeBps = 500 (5%) at settlement. Escrow covers prompt_tokens/4 + max_tokens output-equivalents and the unused remainder is refunded; the charge is the blended token rate × actual tokens. The provider is the one who ran the GPU — that is the whole point of the design.

🏦 Protocol fee

The 5% lands in the token pallet and splits by default 200/150/100/50 bps: 40% staking rewards, 30% treasury, 20% burned, 10% oracle rewards. The burn is a real slash — total issuance falls, not just bookkeeping.

🪙 Emission

50 GPN per 15 s block ≈ 288,000 GPN/day to miners under the halving schedule, capped at ~420.48M emitted, plus a fixed 100M treasury (70M genesis-unlocked, 30M vested) — a hard ceiling of ≈520.5M GPN. Fees are separate from emission: they recycle GPN, they do not mint it.

Scale check: at 2.53 GPN per million tokens, one day of emission (288,000 GPN) buys ≈114 billion output tokens — about 13,000 consumer GPUs running flat out for a day. That is the size of the inference economy the current parameters can subsidise.

Honest caveats

  • Today's inference is free, and that is not a price. The public access point pays job escrow from a hot wallet, so gpncoin.ai/api/v1 costs you nothing while the testnet runs. This section describes the paid model the scheduler is already built for — not what is live.
  • The token has no reliable market price. GPN is a testnet token. Any USD figure here is an illustrative conversion at $0.15/GPN; the GPN-denominated numbers are the real ones. When the on-chain oracle feed is empty (it is today), token_price_usd also falls back to $0.15 — so a change in the feed changes both sides of the ratio.
  • Throughput is measured, not promised. The anchor assumes a 4060-class card reaching 95 tok/s on a 1B model; a slower card earns less per hour, and a card earning below its operator's declared cost is flagged rather than quietly subcontracted. Batching several sequences on one card raises the provider's earning per hour without changing the buyer's price.
  • Small models are not frontier models. A $0.40/M hosted nano model and a $0.38/M GPN 1B model are both "cheap", but neither reasons like gpt-6-astra or Claude Fable 5.1. Cost per useful answer is the only fair denominator, and this page does not have that data.
  • Input metering is channel-first. A cheap request that batches over a channel bills input at 15% of the output rate. An expensive request settles per job on chain, and the pallet stores a single rate, so that path publishes a blended rate that is exact when the completion runs to max_tokens and slightly under-bills short completions. Exact two-rate settlement on chain needs a pallet change; it is tracked, not claimed.
  • No cache pricing, no batch discount, no SLA on the testnet.
