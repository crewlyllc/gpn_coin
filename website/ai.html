Why a proxy?

The testnet access point listens on plain http://…:8092, which a browser on an HTTPS page cannot call. gpncoin.ai/api/* terminates TLS at the edge, rate-limits per IP, and forwards the same request — so your code only ever talks to https://gpncoin.ai.

Four working clients

Every example below is the live endpoint. The testnet ignores the API key, but the OpenAI SDK still requires one — any non-empty string works.

bash 
curl https://gpncoin.ai/api/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "llama3.2:1b",
    "messages": [{"role": "user", "content": "What is the capital of Kenya? One word."}]
  }'

Returns an OpenAI-shaped chat.completion object. Add -m 150 — a cold job can take a minute.

python 
import requests

r = requests.post(
    "https://gpncoin.ai/api/v1/chat/completions",
    json={
        "model": "llama3.2:1b",
        "messages": [{"role": "user",
                      "content": "Explain a GPU compute network in one sentence."}],
    },
    timeout=150,
)
r.raise_for_status()
print(r.json()["choices"][0]["message"]["content"])

No SDK, no key. timeout=150 covers a cold testnet job.

python 
# pip install openai
from openai import OpenAI

client = OpenAI(
    base_url="https://gpncoin.ai/api/v1",
    api_key="gpn-testnet",   # required by the SDK; unused by the testnet
    timeout=150,
)

reply = client.chat.completions.create(
    model="llama3.2:1b",
    messages=[{"role": "user", "content": "Say hi in five words."}],
)
print(reply.choices[0].message.content)

Any OpenAI-compatible library works: base_url is the only change.

javascript 
const res = await fetch("https://gpncoin.ai/api/v1/chat/completions", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    model: "llama3.2:1b",
    messages: [{ role: "user", content: "Say hi in five words." }],
  }),
});

if (!res.ok) throw new Error(`HTTP ${res.status}: ${await res.text()}`);
const data = await res.json();
console.log(data.choices[0].message.content);

Node 18+ (global fetch) or any modern browser.

Capabilities

What you can run today

The job API accepts every GPN work type. Only what a live provider advertises is actually routable — the badges below track what is online right now, not what the protocol can express.

💬 Text / LLM live

OpenAI-compatible chat completions on llama3.2:1b and qwen2.5; the model list is whatever the online providers report.

POST /api/v1/chat/completions
{"model": "llama3.2:1b",
 "messages": [{"role": "user", "content": "Hi"}]}
→ {"choices": [{"message": {"role": "assistant",
     "content": "Hi."}, "finish_reason": "stop"}],
   "usage": {"prompt_tokens": 32, "completion_tokens": 3}}

🎨 Image generation coming soon

The job type and a diffusers-based provider binary exist, but no image model is registered on the testnet right now, so nothing would route.

POST /api/jobs
{"job_type": "ImageGeneration", "model": "sd-turbo",
 "prompt": "a cozy cabin at dusk",
 "width": 512, "height": 512, "steps": 8}
→ {"id": 1234, "state": "Queued"}

🎬 Video generation coming soon

Same job API, heavier host: a text-to-video pipeline needs a large GPU for the encoder. No video provider is online today.

POST /api/jobs
{"job_type": "VideoGeneration", "model": "ltx-video",
 "prompt": "waves at sunset", "seconds": 4}
→ {"id": 1235, "state": "Queued"}

🧮 ML inference coming soon

Run a custom model as an MLInference job with a JSON input/output contract. Capability is advertised by providers; no ML-only endpoint is live yet.

POST /api/jobs
{"job_type": "MLInference", "model": "resnet50",
 "input": {"url": "https://…/cat.jpg"}}
→ {"id": 1236, "state": "Queued"}

🎛️ Fine-tuning coming soon

LoRA fine-tunes are a job type; a completed tune is served back as tuned-<jobid>. The testnet fine-tune worker is not running.

POST /api/jobs
{"job_type": "FineTuning", "model": "llama3.2:1b",
 "dataset": "https://…/data.jsonl", "epochs": 1}
→ {"id": 1237, "state": "Queued"}

Endpoints

All of these are HTTPS on gpncoin.ai and proxy to the live access point. Status codes and JSON bodies are passed through unchanged.

Method & pathWhat it doesLimit
POST /api/v1/chat/completionsOpenAI-compatible chat. Accepts messages[] or a top-level prompt/input.12 calls / 10 min per IP · 64 KB body
GET /api/v1/modelsModel list in OpenAI {"object":"list"} shape.120 / min per IP
GET /api/healthAccess point liveness and provider count.120 / min per IP
GET /api/jobs/<id>On-chain state of a job (Pending, Running, Completed…).120 / min per IP
GET /api/providersLive provider registry: models, capabilities, latency.120 / min per IP
GET /api/modeWhether this AP is testnet (free AI) or mainnet (client-signed).120 / min per IP
Free, but not unmetered

The testnet access point pays escrow from a hot wallet, so a call costs you nothing. Each call is still one GPU job — hence the per-IP cap. For volume, run your own access point or provider node.

Testnet caveats

Prompts and answers are not private (the AP and provider see them; results are stored off-chain). Models are small. No uptime promise — the network is a testnet.
