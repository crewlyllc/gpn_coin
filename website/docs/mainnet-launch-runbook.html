GPN Mainnet Launch Runbook

Audience: the launch operator (currently Jeremy). Status: ready to execute, pending a go/no-go and the open business decisions listed in §10.

This runbook covers standing up the --chain=mainnet network: the genesis artifact, the bootnode/full-node set, post-launch governance actions (block beneficiary, oracle operators), treasury operations, monitoring, verification, and abort/rollback criteria.

Companion docs: - Tokenomics (source of truth): design/tokenomics/01-gpn-tokenomics.md - Pallet map: design/pallets/00-pallet-overview.md - Public testnet runbook: shared/artifacts/project7/testnet-public-runbook.md - Incident response: docs/incident-response.md - Security policy: SECURITY.md

Nothing in this runbook uses sudo on mainnet — the mainnet sudo key is an inert all-zeros placeholder (AccountId::new([0u8;32])) with no private key. Every privileged action listed below is done through root/governance (Sudo-only calls are replaced by a governance runtime call) or the on-chain pallet-gpn-treasury 13-of-25 flow. See §6.

4. Stand up the network (T-0)

There is no validator authority set — GPN is PoW; the "bootnode layer" is a set of always-on, publicly reachable full nodes. A permissionless liveness scheme (pallet-gpn-liveness) rewards reachable full nodes and slashes unreachable ones, so bootnodes emerge organically rather than being founder-funded.

  1. Seed bootnodes (2–4). Each operator runs:
gpn-node --chain /tmp/gpn-mainnet.json \
  --base-path /var/lib/gpn --name <human-name> \
  --node-key-file /etc/gpn/node.key \
  --listen-addr /ip4/0.0.0.0/tcp/30333 --listen-addr /ip4/0.0.0.0/tcp/30334/ws \
  --rpc-port 9944 --rpc-external --rpc-methods=safe \
  --prometheus-port 9615 --prometheus-external

# publish the real peer id
gpn-node key inspect-node-key --file /etc/gpn/node.key

Note: a fresh --base-path requires a --node-key/--node-key-file, otherwise the node fails with NetworkKeyNotFound. Reuse the same key file across restarts so peer IDs are stable. 2. Announce the bootnode list: --bootnodes /ip4/<IP>/tcp/30333/p2p/<PEER_ID> for each. 3. Confirm chain progress. Blocks are only produced by GPU PoW; watch for the first seals:

gpn-node --chain /tmp/gpn-mainnet.json ...   # any full node
# separate terminal
curl -s -H 'Content-Type: application/json' \
  -d '{"id":1,"jsonrpc":"2.0","method":"chain_getHeader","params":[]}' \
  http://127.0.0.1:9944 | python3 -m json.tool

A healthy launch has new blocks every ~10–15 s. If no block appears within ~10 min, treat as a launch incident (see docs/incident-response.md §6.1).

6. Post-launch governance actions (first days)

All of these are root/governance calls (mainnet has no usable sudo). Queue them as a governed Sudo.sudo → <call> or via the governance committee per design/protocols/05-oracle-governance.md.

  1. Set the block-reward beneficiary. Without this, mined blocks pay no one (the genesis beneficiary is None — deliberate, no hardcoded dev backdoor). Set the mining pool / ops account:
gpu_pow.set_block_beneficiary(account)   # call_index 1, root-only

Verify: mine a block, confirm the beneficiary balance rose by exactly the block reward and a BlockRewardPaid event fired (one payment per block — a manual submit_solution claim and the automatic path can never double-pay). 2. Admit oracle operators so the profitability feed is populated:

profitability_oracle.add_operator(account)   # root; then operator posts update_feed

Client-side: an operator runs gpn_operate_oracle ws://<node>:9944 <values.toml> <interval> //<key>. 3. Fund/operate the treasury only through the 13-of-25 flow (§7). 70M is unlocked at genesis (spendable immediately), and 1.5M unlocks every SIX_MONTHS_BLOCKS = 1,036,800 blocks thereafter until the 30M vest completes (10 yr). 4. Publish operator onboarding (operator-onboarding.md) and the RPC endpoint list.

7. Treasury operations (pallet-gpn-treasury)

The 100M allocation sits in the keyless gpn/trsy pallet account. There is no private key; funds move only through the 13-of-25 roster flow, bounded by unlocked tranches.

# read-only
gpn_treasury status      # balance, unlocked, spendable, threshold, roster size
gpn_treasury schedule    # tranches: unlock block, amount, unlocked?
gpn_treasury roster      # roster size + threshold
gpn_treasury proposals   # pending spend proposals

# signed — each signer must be a roster member (real seed phrase or secure URI)
gpn_treasury propose <dest-ss58> <amount-gpn>        --signer <uri1>   # auto-approves as proposer
gpn_treasury approve <proposal-id>                   --signer <uri2>   # repeat to reach 13
gpn_treasury execute <proposal-id>                   --signer <uri1>   # after ≥13 approvals

Rules the pallet enforces: NotInRoster, NotEnoughApprovals (< 13), InsufficientUnlocked (beyond unlocked tranche total), AlreadyExecuted, RosterEmpty. Amounts are whole GPN (converted to 12-decimal base units). Coordinate signers out-of-band; never collect keys in one place.

Minimum alerts: no new block for >2× target (30 s); peer count 0; TotalMinted not advancing; any treasury proposal nearing execution; difficulty collapsing or exploding. The faucet (gpn_faucet) is testnet-only — do NOT run it on mainnet.

9. Abort / rollback criteria

Launch is aborted (announce, stop bootnodes, keep genesis private) if any of: - the genesis hash differs between operators (spec mismatch), or - genesis verification in §3 fails (wrong endowment / non-null beneficiary / wrong initial_minted / oversized roster), or - the WASM runtime hash does not match the published release binary, or - > 10 min with zero blocks and no mining explanation.

There is no chain rollback tool worse than re-genesis: if a fatal genesis bug ships, the network must be restarted from a corrected spec at block 0 (nothing of value exists yet). After value exists, recovery is governance-driven and slow by design — which is why §3/§5 verification is non-negotiable.
