GPN · Do AI Work on the Network

A quick-start guide to LLM chat, image & video generation, and fine-tuning on a GPU compute network.

The big idea

The GPN chain is coordination + escrow: it records job specs, prices, and a sha256 hash of every result — so work is provable and paid on-chain. But it deliberately does not carry prompts, models, or generated files on the ledger. All the heavy data moves off-chain between you and the provider's GPU, and the chain just settles the deal.

Which models can I use?

Any model the provider has. The network isn't locked to one model. The job's model field is passed straight to the runtime, so:
KindHow to use a different model
LLM chatAny model pulled into ollama: llama3.2, qwen2.5-coder, mistral, gemma, phi… or your tuned ones (tuned-1). Just set "model": "<that id>" on the job.
Image genAny diffusers text-to-image model id (e.g. sd-turbo, sd15, or an SDXL/FLUX id the provider supports).
Fine-tuneAny HuggingFace causal-LM id as the base (small ones fit this GPU best).
8 GB VRAM reality: fits roughly 1–8B quantized LLMs for chat, SD-class image models, LoRA fine-tuning of small models. Video diffusion and big 70B models need a bigger GPU — the code is ready, the hardware isn't.

Bring your own model (BYO)

The dapp/API accept any model the provider already has loaded. To add a model the provider doesn't have yet, put it in ollama on the provider machine:

# pull from Hugging Face / ollama's registry
ollama pull llama3.2:1b        # any supported chat model

# register a GGUF you already have
ollama create mymodel -f Modelfile   # FROM ./my-model.gguf

Then just use "model":"llama3.2:1b" (or whatever) in your job. No weights ever touch the chain.

Script it with the REST API

1 · Onboard a provider (once)

curl -X POST http://127.0.0.1:8082/providers/register -H 'Content-Type: application/json' -d '{"min_gflops":800}'
curl -X POST http://127.0.0.1:8082/providers/stake    -H 'Content-Type: application/json' -d '{"amount_gpn":1000}'
curl -X POST http://127.0.0.1:8082/providers/attest   -H 'Content-Type: application/json' -d '{"gpu_count":1,"compute_gflops":831,"gpu_info":"RTX 4060 8GB"}'

2 · Run an LLM job

curl -X POST http://127.0.0.1:8082/jobs -H 'Content-Type: application/json' -d '{
  "job_type":"LLMInference","model":"qwen2.5:1.5b",
  "prompt":"Explain a GPU compute network in two sentences.",
  "price_gpn":2.5,"min_gflops":800,"max_tokens":150}'
# → {"job_id":3,"ok":true,"bridged":true}
curl -X POST http://127.0.0.1:8082/jobs/3/accept
curl -X POST http://127.0.0.1:8082/jobs/3/start
# provider runs it on the GPU, settles escrow on-chain…
curl http://127.0.0.1:8082/job/3/result
# → {"job_id":3,"status":"done","response":"A GPU compute network …","result_hash":"901dc5…"}

3 · Generate an image

curl -X POST http://127.0.0.1:8082/jobs -H 'Content-Type: application/json' -d '{
  "job_type":"ImageGeneration","model":"sd-turbo",
  "prompt":"a cozy cabin in a snowy pine forest at dusk, warm light",
  "negative_prompt":"blurry","width":512,"height":512,"steps":8,
  "price_gpn":5,"min_gflops":800}'
# accept + start, then fetch the PNG:
curl http://127.0.0.1:8082/job/4/artifact -o out.png   # → image/png

4 · Fine-tune a model (LoRA)

curl -X POST http://127.0.0.1:8082/jobs -H 'Content-Type: application/json' -d '{
  "job_type":"FineTuning","model":"HuggingFaceTB/SmolLM2-135M-Instruct",
  "dataset":[{"prompt":"What is the secret code?","completion":"TAG42"}],
  "lora_r":16,"epochs":3,"price_gpn":10,"min_gflops":800}'
# accept + start. When it completes, it auto-serves as model "tuned-<jobid>",
# and you can download the adapter:
curl http://127.0.0.1:8082/job/5/artifact -o adapter.zip

Why it's honest & private

  • Chain = verification, not data. Only result hashes settle on-chain, so prompts, models, and outputs stay off the public ledger.
  • Providers must prove their GPU (attestation) before they can take paid jobs.
  • Escrow protects both sides — requestor locks funds, provider is paid on a verified result.
